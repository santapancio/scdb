### Fundamentos de la base de datos
- el objetivo de SCDB es formalizar y organizar las operaciones de SC, y permitir la correcta coordinación de la organización al escalar sus actividades
- está compuesta por tres sistemas:
    - recursos
    - delegaciones
    - iniciativas
- existen otros sistemas ya diseñados, pero no están implementados aún:
    - personas
    - privilegios
    - historial
    - conocimiento
- la separación de sistemas es para facilitar la prolijidad, modularidad y modificación sobre la marcha
- YAML como formato para todos los elementos porque está pensado para ser fácilmente legible y editable por humanos y también por máquinas en simultáneo
- git porque nos da hosting, acceso colaborativo, control de versiones y una API gratis, entre otras cosas
- ID de la base de datos = nombre de archivo = nombre descriptivo. un identificador, tres propósitos. reduce la complejidad
- las referencias son la manera de comprender las relaciones entre elementos
- en el futuro, muchas de estas cosas serán automatizadas o asistidas por software
- ninguno de estos sistemas está estrictamente ligado a los otros, pueden funcionar independientemente en su ámbito
    - una delegación puede administrar varias iniciativas
    - una iniciativa puede involucrar varias delegaciones
    - varias delegaciones pueden utilizar el mismo recurso
    - una delegación puede usar varios recursos
    - una iniciativa puede existir sin que haya una delegación dedicada a ella
    - estas relaciones se registran mediante referencias en SCDB
- los sistemas deliberadamente no formalizan sus interacciones
    - cada sistema registra los hechos que le corresponden y las relaciones relevantes deberían poder expresarse mediante referencias entre elementos
    - las interacciones entre sistemas son más que nada informales, y luego se ven reflejadas en los datos
- la realidad es mucho más compleja e informal que este sistema y no es inteligente intentar evitarlo. por eso, se supone que estos sistemas se conformen a la realidad y no viceversa
- las guías de cada sistema sirven para dar a entender el funcionamiento de cada sistema en particular por encima de esta guía general
- las plantillas de cada sistema sirven para copiar y pegar en un elemento nuevo al crearlo para llenar su información
- la base de datos debe ser mantenida continuamente con tal de que siga reflejando la realidad
### Formato
- propiedades de los elementos
    - 1 elemento = 1 archivo con extensión ".yaml"
        - nombres legibles y entendibles
        - en minúscula y sin espacios (usar "-")
        - ejemplo: "servidor-principal.yaml"
    - no puede haber dos elementos con el mismo ID en toda la base de datos entera

- propiedades del contenido de los elementos
    - la sintaxis YAML debe ser correcta
    - cada sistema tiene su propio formato
        - la plantilla explica qué significa cada campo (por ej. "detalle") y qué corresponde poner en él, incluyendo su formato
        - no se deberían agregar o restar campos en ningún caso
        - la mayoría de los campos pueden estar vacíos y su contenido puede ser cualquier cosa mientras se respete la plantilla
    - la mayoría de los campos pueden estar vacíos
        - dejar un campo vacío es preferible a introducir información inventada. la información especulativa es aceptable, pero debe entenderse que es tal
    - referencias
        - se hacen mediante los IDs de los elementos de SCDB
        - una referencia se escribe entre dobles corchetes: [[id]]
            - ej. [[iniciativa-ejemplo]], [[recurso-ejemplo]], [[delegacion-ejemplo]]
        - las referencias deben utilizarse siempre que sea relevante y posible
            - nos ahorrará trabajo en el futuro que ya haya referencias hechas desde el día 1
        - se puede hacer referencias entre sistemas, y muchas veces va a ser necesario
        - las referencias deben apuntar a elementos existentes
        - cuando se cambia un ID, deben actualizarse las referencias que apuntan al ID anterior
        - las referencias deberían ser bidireccionales

- el anidado de los elementos no está ligado a u obligado a seguir el de los directorios de SCDB, y puede hacerse como se desee
